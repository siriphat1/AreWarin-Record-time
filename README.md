# AreWarin Tutor OS v2.1.0 — Hourly Tuition & Course Renewal

เวอร์ชันต่อยอดจาก v2.0.2 โดยเพิ่มการเรียน **รายชั่วโมง (Pay per Hour)** การรับชำระเงินค่าคาบ และการต่อคอร์สรายชั่วโมงพร้อมเก็บประวัติแต่ละรอบไว้ โดยไม่กระทบระบบแพ็กเกจชั่วโมงเดิม

## เริ่มใช้ระบบรายชั่วโมง

1. ไปที่ **นักเรียนและคอร์ส → เพิ่มนักเรียน** และกรอก **ราคาเริ่มต้นต่อชั่วโมง (บาท)** เช่น `450` (ไม่บังคับ) หากสร้างนักเรียนใหม่และใส่ราคามากกว่า 0 ระบบสร้างคอร์ส `เรียนรายชั่วโมง` รอบ 1 อัตโนมัติ
2. สำหรับนักเรียนเดิม ไปที่ **เพิ่มคอร์ส → รูปแบบคอร์ส: เรียนรายชั่วโมง** ระบุชื่อคอร์ส วันเริ่ม และราคา/ชั่วโมง (ไม่ต้องซื้อชั่วโมงล่วงหน้า)
3. ไป **Record Hours** หรือ **Import Google Meet Excel** เลือกนักเรียนและคอร์สรายชั่วโมง ระบบคิดค่าเรียนจากนาทีที่บันทึกโดยใช้ราคา/ชั่วโมง ณ รอบคอร์สที่เลือก
4. ผ่านหน้า Final Review แล้วกดบันทึก รายการจะอยู่สถานะ **รอชำระ**; ระบบไม่หักจาก Hour Ledger ของแพ็กเกจ
5. เปิดเมนู **ค่าคาบรายชั่วโมง** เพื่อดูรายการตามวันและนักเรียน เลือก **รับชำระแล้ว** ระบุวิธีรับชำระและติ๊กยืนยันก่อนปิดยอด
6. เมื่อนักเรียนเรียนต่อ ไปที่ Student Profile → คอร์สรายชั่วโมง → **ต่อคอร์ส** เลือกวันเริ่มและราคา/ชั่วโมงรอบใหม่ คอร์สเก่าจะเป็น `archived` แต่ใบรายการเก่า รวมทั้งค่าคาบค้างชำระยังคงอยู่

ตัวอย่าง: 450 บาท/ชม. × 90 นาที = **675.00 บาท**; รอบใหม่ 500 บาท/ชม. × 90 นาที = **750.00 บาท**. ค่าคาบคิดเป็นหน่วยสตางค์จำนวนเต็มเพื่อเลี่ยงความคลาดเคลื่อนทศนิยม

## วิธีอัปเกรด Google Sheets (จำเป็นสำหรับ v2.1)

> **สำคัญ**: เวอร์ชันนี้ **เปลี่ยนโครงสร้างชีต** ต่างจาก v2.0.2. สำรอง Google Sheets เดิมก่อนทำขั้นตอนนี้

1. เปิด Google Sheets ที่ใช้เก็บข้อมูล AreWarin Tutor OS จริง → **Extensions → Apps Script**
2. แทนที่โค้ดตั้งต้นด้วย `apps-script/Setup.gs` ของ v2.1 (หรืออัปเดตเฉพาะ `TUTOR_SCHEMA` ให้ตรงกับไฟล์นี้)
3. เลือกฟังก์ชัน `setupTutorOS` แล้วกด Run; ตรวจสอบข้อผิดพลาดและสิทธิ์ที่ Google ขอ
4. ตรวจสอบว่า `Students` มีคอลัมน์ใหม่ท้ายแถวชื่อ `hourly_rate_baht`; `Courses` มีคอลัมน์ `billing_mode` และ `hourly_rate_baht` **ท้ายสุด**; และมีชีตใหม่ `Billing` พร้อมหัวคอลัมน์
5. อัปโหลด `index.html`, `assets/app.js`, `assets/style.css` รุ่นใหม่ขึ้น GitHub Pages แล้วเปิดเว็บไซต์ใหม่แบบ Hard Refresh
6. **เก็บ `config.js` จริงของคุณไว้** ไม่คัดลอกตัวอย่างจาก ZIP มาทับค่าที่ใช้เชื่อม Google Sheets

`setupTutorOS` จะตรวจหัวคอลัมน์เดิมและต่อท้ายคอลัมน์ใหม่ ไม่ล้างข้อมูลเดิม ถ้าโครงสร้างเดิมต่างจากที่คาด จะหยุดพร้อมข้อผิดพลาด; อย่าลบคอลัมน์หรือย้ายตำแหน่งเอง

### โครงสร้างใหม่

- `Students.hourly_rate_baht` — ราคาเริ่มต้นรายชั่วโมงของนักเรียน (ใช้ตั้งคอร์สใหม่ ไม่เปลี่ยนอัตราเดิม)
- `Courses.billing_mode` — `package` หรือ `hourly` (คอร์สเก่าที่ว่างให้ถือเป็น `package`)
- `Courses.hourly_rate_baht` — ราคา/ชั่วโมงเฉพาะรอบคอร์ส (snapshot ไม่แก้ย้อนหลัง)
- `Billing` — `id`, `attendance_id`, `student_id`, `course_id`, `session_id`, `minutes`, `rate_baht`, `amount_satang`, `status`, `paid_at`, `payment_method`, `note`, `created_at`, `updated_at`

สถานะ `Billing`: `unpaid` (ยังไม่ชำระ), `paid` (ชำระแล้ว), `void` (ยกเลิกรายการที่ยังไม่ชำระ), `refund_due` (ยกเลิกหลังชำระ ต้องคืนเงินจริง), `refunded` (ยืนยันคืนเงินจริงแล้ว)

## การทำงานร่วมกับคอร์สแพ็กเกจ

- คอร์สแพ็กเกจเดิมยังใช้ `Ledger` ตามปกติ: บันทึกและตัดชั่วโมงทันที
- คอร์สรายชั่วโมงเก็บจำนวนเวลาเรียนใน Attendance และสร้างค่าคาบใน `Billing` **ไม่หักชั่วโมงแพ็กเกจ**
- นักเรียนคนเดียวสามารถมีคอร์สแพ็กเกจและคอร์สรายชั่วโมงพร้อมกันได้; ผู้บันทึกต้องเลือกคอร์สให้ตรงทุกครั้ง
- เมื่อชำระเงิน รายการ `Billing` จะเปลี่ยนสถานะ; คาบเรียนและวันที่ยังอยู่ใน Learning History
- การต่อคอร์สรายชั่วโมง **ไม่ลบหรือยกยอดค่าคาบค้างชำระ**; ค่าคาบแต่ละรายการอยู่กับรอบคอร์สเดิม

## ข้อจำกัดและความปลอดภัย

- ปุ่ม “รับชำระแล้ว” เป็นการ **ลงบัญชีด้วยมือ** ไม่ใช่การตรวจสอบธุรกรรมธนาคารหรือชำระเงินจริงอัตโนมัติ
- ตัวแอปยังใช้ Google OAuth + Sheets API โดยตรงจาก GitHub Pages และยังไม่ได้ผ่านการทดสอบจริงในบัญชี Google ของผู้ใช้; ควรทดสอบบนสำเนาฐานข้อมูลก่อน
- Google Sheets API ผ่านเบราว์เซอร์ **ไม่ได้มีการล็อกธุรกรรมที่เพียงพอสำหรับผู้ใช้หลายคนเขียนพร้อมกัน** หากเปิดใช้หลายแอดมินพร้อมกัน ควรย้ายธุรกรรมเงินและชั่วโมงไปยัง Backend ที่รองรับ atomic operation / idempotency
- อย่านำ `Client Secret`, access token, หมายเลขบัญชี หรือข้อมูลนักเรียนที่ละเอียดอ่อนไปไว้ใน GitHub repository สาธารณะ
- รายการ `Pending` รุ่นเก่าจะไม่ถูกตัดย้อนหลังอัตโนมัติ
