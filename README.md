# AreWarin Tutor OS v1.8 — Direct Save & Classroom Calendar

Web app บริหารนักเรียนและชั่วโมงเรียนแบบ GitHub Pages + Google Sheets API (Google Apps Script ใช้ตั้งค่าชีตเริ่มต้น) เน้นการบันทึกครั้งเดียวและตัดชั่วโมงทันที **หลังผู้ใช้ตรวจหน้า Final Review และยืนยัน**

## มีอะไรใหม่ใน v1.8

1. **Record Hours**: เลือกวันที่ เวลาเริ่ม–สิ้นสุด ระบบแสดงระยะเวลาเป็น `1 ชม. 30 นาที` อัตโนมัติ ไม่ต้องเลือกวิธีตัดชั่วโมงซ้ำอีก หลัง Final Review ระบบบันทึกคาบ + Attendance + Hour Ledger ในชุดเดียว
2. **Excel Import**: รองรับหลายไฟล์ อ่านวันที่จากข้อมูล Excel ก่อน (ถ้ามี) มิฉะนั้นอ่านจากชื่อไฟล์ แต่ละไฟล์เก็บวันที่แยกกัน ป้องกันไฟล์ซ้ำด้วย fingerprint และตรวจเวลาที่ทับซ้อนกันระหว่างนักเรียน/ไฟล์ เมื่อบันทึกสำเร็จจะตัดชั่วโมงทันที แล้วล้างพื้นที่อัปโหลดพร้อมใช้งานชุดใหม่
3. **Final Review**: แสดงวันที่แต่ละคาบ นักเรียน คอร์ส เวลาจริง เวลาที่จะหัก และยอดก่อน–หลัง จากนั้นให้ติ๊กรับรองก่อนกดยืนยัน **ไม่มี Pending สำหรับรายการใหม่**
4. **ยกเลิก/คืนชั่วโมง**: นักเรียนมีปุ่มยกเลิกรายการจาก Recent Attendance สามารถคืนชั่วโมงเฉพาะคนนั้นได้ หากยกเลิกคาบทั้งกลุ่มภายหลัง จะไม่คืนซ้ำให้คนที่ยกเลิกไปแล้ว ข้อมูลเก่าคงอยู่ใน Audit และ Ledger
5. **คาบเก่าที่ Pending**: ไม่ถูกตัดย้อนหลังเอง หน้า Dashboard จะแสดงคำเตือน ให้ไปเมนู “ประวัติและแก้ไข” เพื่อเลือกและยืนยันตัดรายการเก่าครั้งเดียว
6. **Class Schedule และวันเรียน**: แสดงทั้งคาบตามกำหนดและคาบที่บันทึกจริงจาก Record Hours / Excel มีมุมมองรายสัปดาห์/ตาราง; Dashboard แสดงรายชื่อที่สอน **วันนี้** จากตารางเรียน
7. **Student Profile**: แสดงวันเรียนที่กำหนดไว้และประวัติการเรียนที่บันทึกตามวันที่ พร้อมระยะเวลาแบบอ่านง่าย
8. **เพิ่ม/แก้ไขนักเรียน**: มีส่วน “กำหนดวันเรียน (ไม่บังคับ)” โดยระบุวันที่ เวลา ติวเตอร์ และรายสัปดาห์ แล้วเชื่อมกับ Class Schedule
9. **ลงคอร์สเพิ่ม**: จากโปรไฟล์สร้างคอร์สใหม่ หรือเลือกชื่อคอร์สที่มีอยู่เป็นต้นแบบ (สร้างยอดชั่วโมงแยกของนักเรียน) รองรับเลือกกลุ่มเรียนพร้อมเพิ่มสมาชิก
10. **Loading UX**: มีหน้าต่างโหลดเมื่ออ่าน Excel หรือบันทึกข้อมูล ผ่าน SweetAlert2 เมื่อโหลดได้ และ fallback ในระบบเมื่อ CDN ใช้ไม่ได้

## อัปเกรดจาก v1.7.1

1. **สำรอง Google Sheets และไฟล์เว็บก่อน** รวมถึง `config.js` เดิม
2. แตก ZIP แล้วนำ `index.html`, `assets/app.js`, `assets/style.css` ไปแทนบน GitHub Pages (ควรวางผ่าน Git commit เพื่อย้อนเวอร์ชันได้)
3. รักษา **`config.js` เดิม** ซึ่งมี Google OAuth Client ID และ Spreadsheet ID ของคุณ ไม่ต้องใช้ไฟล์ว่างใน ZIP ถ้าเคยตั้งค่าแล้ว
4. รอ GitHub Pages อัปเดต และรีเฟรชหน้าเว็บแบบ Hard Reload (`Ctrl + Shift + R`)
5. ทดลอง 1 คาบกับนักเรียนทดสอบ ตรวจว่าตาราง `Sessions`, `Attendance`, `Ledger` เพิ่มข้อมูลและยอดคงเหลือเปลี่ยนทันที

**ไม่ต้องรัน `Setup.gs` ใหม่** หากมาจาก v1.7.1 ที่ตั้งค่าสมบูรณ์ เพราะ v1.8 ไม่เพิ่มคอลัมน์/ชีตใหม่ ใช้ schema เดิมทั้งหมด

## ขั้นตอนบันทึกเวลา

**Manual:** Record Hours → วันที่+เวลา → นักเรียน/คอร์ส → ตรวจหน้าสรุป → ติ๊กถูก → “ยืนยันบันทึกและตัดชั่วโมง”

**Excel:** Import Excel → ลากหลายไฟล์ → ดูตารางวันที่/เวลาแต่ละไฟล์ → ตั้งค่าชั้นเรียน/แหล่งเวลาที่ต้องการ → จับคู่ชื่อ Meet → ตรวจหน้าสรุป → ติ๊กถูก → “ยืนยันบันทึกและตัดชั่วโมง” → หน้า Import เคลียร์พร้อมใช้ต่อ

ค่าเวลาในรายงานอาจต่างจากเวลาที่เลือกใช้หักได้ ตาราง Final Review แยก **เวลาจริง** กับ **เวลาที่หัก** และบันทึกตามแพ็กเกจของนักเรียนแต่ละคน

## วิธีจัดการข้อมูล Pending เดิม (สำคัญ)

ไฟล์ที่บันทึกไว้ก่อน v1.8 อาจมีสถานะ `pending` อยู่แล้ว และ **ยังไม่ได้หักชั่วโมง** อย่านำไฟล์นั้นมา Import ซ้ำ เพราะ fingerprint จะกันไว้ ให้ใช้เมนู **ประวัติและแก้ไข → เลือกรายการเก่าที่ยังไม่ตัด → สรุปก่อนยืนยัน → ตัดชั่วโมงรายการเก่า** ตรวจวันที่และยอดก่อนยืนยัน เพราะรายการที่เคยปรับยอดชั่วโมงด้วยมืออาจได้รับผลกระทบจากการตัดย้อนหลัง

## การยกเลิก Recent Attendance

กดเปิดโปรไฟล์นักเรียน → ประวัติการเรียนตามวันที่ → **ยกเลิกรายการ** ระบบยกเลิกอย่างปลอดภัยและคืนยอดที่เคยตัด โดยยังเก็บแถวประวัติไว้ ไม่ใช่ลบหลักฐานถาวร

**ป้องกันซ้ำ:** มีทั้งการตรวจ fingerprint สำหรับไฟล์เดิม และเช็กเวลาเข้าร่วมทับซ้อนในวันเดียวกันสำหรับนักเรียนเดียวกัน ทั้ง Manual และ Excel ภายในชุดเดียว / ข้อมูลที่โหลดมา ข้อจำกัด: หากหลายผู้ใช้บันทึกพร้อมกันจากหลายแท็บ/อุปกรณ์บน Google Sheets API แบบตรง อาจยังเกิด race condition ได้ ควรใช้ผู้ดูแลหนึ่งคนบันทึกต่อครั้ง หากต้องการบันทึกพร้อมกันหลายผู้ใช้อย่างปลอดภัยต้องย้ายธุรกรรมไป backend ที่มี locking/unique constraints

## โครงสร้างที่ใช้

- `index.html` เว็บหลัก
- `assets/app.js` งานประมวลผลและอินเทอร์เฟซ
- `assets/style.css` ธีม responsive
- `config.js` ตัวระบุ OAuth/Sheet **ว่างใน ZIP ตัวอย่าง**
- `apps-script/Setup.gs` ตั้งค่า Google Sheets เฉพาะติดตั้งครั้งแรก
- `samples/` ไฟล์ตัวอย่าง
- `tests/` Node smoke tests และ browser integration test

## ความปลอดภัยและข้อจำกัด

- **อย่าใส่ Client Secret, access token, รหัสผ่านลงใน GitHub Pages** และอย่า Publish Google Sheets เป็นสาธารณะ
- ต้องได้รับสิทธิ์ Google OAuth ในโปรเจกต์ที่ถูกต้อง; เมื่อโทเคนหมดอายุ อาจต้องลงชื่อเข้าใช้อีกครั้ง
- เอกสารตัวอย่างใช้ Demo mode เก็บข้อมูลในเบราว์เซอร์ ไม่ใช่ฐานข้อมูลจริง
- ตรวจโค้ดและทดสอบใน Chromium/Node ด้วยข้อมูลจำลองแล้ว แต่ **ยังไม่ได้ทดสอบกับ Google Sheets ของคุณโดยตรง** สำรองก่อนใช้งานจริงเสมอ
- ไม่รวมระบบ shared wallet กลุ่มแบบหักหนึ่งครั้งต่อแพ็กเกจกลางในรุ่นนี้ (หักตามแพ็กเกจรายนักเรียนตามที่เลือก)
